# Стенд stage.umedu.ru

Отдельная копия кода и отдельная база. На нём показывают ветку до выкатки на umedu.ru.
Прод и сервер этим файлом не меняются: скрипты запускает человек с доступом к серверу.

Регистрация на стенде открытая (`CQ_SIGNUP=open`). Включены тема umedu, раздел `/u2` и флаг `CQ_STAGE=1`:
на каждой странице плашка «Тестовый стенд, данные могут быть стёрты» и заголовок `X-Robots-Tag: noindex`.
Повторный запуск скриптов безопасен: env не перезаписывается, демо-данные второй раз не дописываются.

## Что нужно до запуска

Скрипт сам это не создаёт. Пока пунктов нет, `add_stage.sh` без `--dry-run` остановится и ничего не запишет
(кроме проверки: без root он выходит ещё раньше).

1. **DNS.** Запись `stage.umedu.ru` (или другой домен, который передаёте аргументом) указывает на этот сервер.
2. **Deploy key только на чтение.** Файл `/etc/codequest/deploy_key`, права `600` или `400`.
   В GitHub это Deploy key репозитория `kakaxy4-wq/umedu` с выключенным Allow write access.
   На сервере в `~/.ssh/known_hosts` должен быть ключ github.com, либо скрипт примет его сам
   (`StrictHostKeyChecking=accept-new`).
3. **Свободный порт** от 1024 до 65535. Для одобренного стенда — `8091`.
   Uvicorn слушает его на всех интерфейсах, чтобы контейнер nginx дотянулся до хоста.
   Снаружи порт закрывает ufw: пускается только подсеть docker-сети Traefik.
4. **Docker-сеть Traefik** (по умолчанию имя `traefik`), entrypoint `websecure` и certresolver `letsencrypt`.
   Если у вас другие имена, задайте перед запуском `CQ_TRAEFIK_NETWORK`, `CQ_TRAEFIK_ENTRYPOINT`,
   `CQ_TRAEFIK_CERTRESOLVER`. Скрипт не включает ufw сам: если он выключен, правило сохранится,
   но действовать начнёт только после `ufw enable`.

Посмотреть, что скрипт сделает, не трогая диск:

```bash
deploy/add_stage.sh --dry-run stage stage.umedu.ru 8091 main
```

## Первый запуск

Из корня репозитория, от root:

```bash
deploy/add_stage.sh stage stage.umedu.ru 8091 main
```

Аргументы: имя, домен, порт, ветка. Имя `stage` кладёт код в `/opt/codequest-stage`
(отдельный clone, не каталог прода), env в `/etc/codequest/stage.env`, базу в `/var/lib/codequest-stage`,
службу `codequest-stage.service`. Рабочий каталог службы — эта копия кода.

Скрипт сам вызывает `manage.py migrate` и `manage.py seed_demo`. В конце печатает демо-вход.
Пароли ниже действуют, только если учётки создал `seed_demo`. Если преподаватель уже был
(его заводили через `manage.py init`), его пароль не меняется.

| Кто | Логин | Пароль |
|---|---|---|
| Преподаватель, если его ещё не было | teacher | demo-teacher |
| Ученица | demo | demo-anya |
| Ещё двое в том же классе | demo-misha, demo-kate | demo-misha, demo-kate |
| Родитель ученицы demo | demo-parent | demo-parent |

Это стенд: данные учебные, их можно стереть. Настоящие фамилии, телефоны и почту туда не кладут.

Проверка: `curl -fsS http://localhost:8091/healthz` и в браузере `https://stage.umedu.ru` —
плашка стенда на месте, страница не для индексации.

## Обновить ветку на стенде

```bash
deploy/update_stage.sh --dry-run имя-ветки
deploy/update_stage.sh имя-ветки
```

Порядок: `git fetch` → pytest на кандидате в отдельном worktree и с временной базой →
только потом переключение `/opt/codequest-stage` → `systemctl restart` → `healthz`.
Если тесты падают, живая копия и служба остаются как были.

Без аргумента берётся ветка из `/etc/codequest/stage.instance`. Другой стенд: `--name имя`.

## Показать ветку и убрать демо

Повторный `seed_demo` пишет «база не изменена». Стереть базу стенда можно, остановив службу
и удалив `/var/lib/codequest-stage` — прод при этом не затрагивается. Потом снова `add_stage.sh`:
env на месте, базу создаст migrate.
